# Feature: Assessment elapsed-time display

**From build-plan:** feature 4.11b
**Status:** complete
**Branch:** `feature/assessment-freshness`
**Audit:** recommended - changes the presentation of clinical timestamps and missing data across the case summary and review drawers.

## Goal

Show when displayed measurements happened separately from when staff entered them.
Use neutral elapsed-time wording for the fictional demo, without implying that a
measurement is current, normal, clinically fresh or safe.

## Approved policy

- The user chose neutral elapsed-time wording: show measured age and entry time,
  and explicitly state when measurement time is unknown.
- No hospital freshness thresholds or fresh/stale classifications are approved.
  These remain deferred; this item does not implement the original plan's
  hospital-threshold wording. This decision is recorded here for spec approval.
- The proposed demo-reset action is separate and is not included here. Never
  rewrite stored times or fabricate recent measurements for presentation.

## Design reference

Use the delivered PatientOverviewPanel, ClinicalReviewDrawer and
TimelineReviewDrawer layouts and their existing typography/SCSS modules.
The canonical reference is
`blueprint/reference/patient-overview/VETIFLOW_ER_OVERVIEW_SPECIFICATION.md`,
with its README's safety and responsive-navigation guidance. This is a bounded
metadata/copy change to existing surfaces, not a new screen or design recreation.

## In scope

- Consume the nullable `occurredAt` contract delivered by 4.11a. Update client
  assessment types, board pain-summary type where applicable, and synthetic
  builders/fixtures to match the server's additive contract.
- On the latest recorded vitals in the compact summary and Clinical drawer,
  show valid event time as `Measured <elapsed age>` and distinguish the existing
  entry time with `Entered <date-aware time>` and recorder identity when known.
- On each existing vitals-entry row in the Timeline drawer, show that record's
  measured age/event time separately from its entry time. Replace the blanket
  claim that separate event/measurement times are unavailable with accurate,
  record-specific wording.
- Reuse the existing `useNow` clock so elapsed labels advance without refetching.
  Keep latest-vitals selection and timeline sorting based on entry time.
- Preserve readings, findings, missing values, loader/refusal behavior, accessibility,
  read-only drawer behavior, navigation and unsaved-change protection.

## Out of scope

- Clinical freshness thresholds, stale/normal/abnormal interpretation, alert
  colours, overdue reassessment changes or automatic recommendations.
- Event-time entry controls (the approved clinical workflow/4.11c), demo resets,
  seed-time refresh changes, backend/API/schema changes and new dependencies.
- New triage/pain review sections, generic pain panels, assessment-change summaries
  (4.8g), or new history sources. The current Clinical drawer presents latest
  vitals/findings; the Timeline merges actual case events and vitals entries.
- Guessing an association between a generic triage CaseEvent and an assessment
  from timestamps alone, duplicating triage milestones, or inferring performers.
- Changing timestamps, assessment order, latest selection or case clinical state.

## Data / contracts

- No new HTTP route, field, migration, enum, hub payload or write request. Reuse
  GET /api/cases/{id} and 4.11a's nullable assessment `occurredAt` values.
- Client assessment interfaces reflect `occurredAt: string | null`; rendering also
  tolerates omitted fields from older responses/fixtures as unknown.
- `recordedAt` remains entry time for vitals/pain; legacy triage `assessedAt`
  remains entry time despite its name. Recorder identity is not performer proof.
- Valid vitals occurredAt: `Measured less than 1 min ago` below one minute,
  whole elapsed minutes below one hour, whole hours below one day, then whole
  days, always rounded down and correctly singular/plural. This is elapsed
  age only, not a clinical judgement. Show the corresponding date-aware absolute
  event time in the Clinical and Timeline views; keep the summary compact.
- Show entry time separately as `Entered ...`; use `Entered by ...` where an
  actor label is needed. Do not call the recorder the measuring clinician.
- Null/omitted occurredAt: `Measurement time unknown`. Invalid timestamps:
  `Measurement time unavailable`. Future instants: `Measurement time is in the
  future`; show no negative age and do not silently clamp to a recent measurement.
  Existing client-clock skew is not authority to modify the source record.
- Invalid entry time: `Entry time unavailable`; do not emit an invalid HTML
  time element or let date formatting crash the panel. No vitals remains
  `No vitals recorded`; missing readings/findings remain missing.
- Absolute labels use local date/time, include the year across calendar years,
  and distinguish ambiguous daylight-saving times when applicable. Elapsed age
  compares instants, not local clock strings. Reuse the current 30-second clock.
- Timeline generic CaseEvents retain `Recorded`/CreatedAt; tasks retain created,
  scheduled due and resolved metadata. Those timestamps do not prove performance.
  Only vitals rows have a supported measured-time source on these existing views.
- Keep same-time stable ordering and invalid-entry ordering from the current
  timeline implementation. Never sort by occurredAt or infer it from entry time.

## Security

- No new access surface or client role/permission decision. Preserve existing
  authenticated API loading and 401/403 session/refusal exits, 404 handling,
  selected-case boundaries and stale-response protection.
- Drawers remain read-only and use their supplied CaseDetail; no independent
  fetch, retry, timestamp mutation, clinical-entry control or reset action.
- Never log clinical data or add browser persistence. Preserve focus restoration,
  close behavior and unsaved-input guards. Unknown actors remain unknown.
