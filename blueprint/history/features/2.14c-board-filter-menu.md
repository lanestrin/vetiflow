## Goal

The board's **Filter** button opens a small menu that narrows the cards by
clinician, species and case status, so staff can see, for example, only
Dr. Reed's patients or only the cats.

## Design reference

The prototype (`blueprint/reference/vetiflow-er-dashboard.html`) has only the
button: `<button class="toolbtn" id="filter">⚑ <span>Filter</span></button>`.
Pressing it toasts "Filters: clinician · species · case status". The menu
below is a proposal in the prototype's visual language, and approving this
spec approves it:

```
 Patient flow                              [⇣ Incoming 1] [⚑ Filter 2]
 Updated just now · 10 active cases                       ┌──────────────────────┐
                                                          │ Clinician            │
                                                          │ [ Reed            ▾] │
                                                          │ Species              │
                                                          │ [ Any species     ▾] │
                                                          │ Case status          │
                                                          │ [ Waiting         ▾] │
                                                          │          Clear filters│
                                                          └──────────────────────┘
```

- **The button:** a `.toolbtn` like Incoming, with "⚑ Filter", and the number
  of filters in use in bold when there are any ("⚑ Filter 2"). It is navy (as
  pressed) while any filter is in use, and the label hides at 650px, as
  Incoming's does.
- **The menu:** a panel under the button, right-aligned. It is styled like the
  profile menu: white, `--color-shell-line` border, radius 10px, the shell's
  shadow, padding 12px, about 220px wide. It holds three labelled native
  selects (11px/600 muted labels, 12px selects) and a **Clear filters** text
  button in teal, which only shows while a filter is in use.
- **Behaviour:** like the profile menu and **•••**: the button has
  `aria-expanded`, Escape or a click outside closes the menu, and Escape
  returns focus to the button. Choosing an option filters straight away; there
  is no Apply button.

## In scope

- **Options, built from the cards on the board:**
  - **Clinician:** "Any clinician", "Unassigned", then each clinician shown on
    a card (its `clinician`: the doctor, else the technician), by short name.
  - **Species:** "Any species", then each species on the board.
  - **Case status:** "Any status", then each status on the board, with a
    staff label: Unassigned, Assigned, Waiting, In progress, Blocked, Ready
    for next step, Completed.
  - A chosen option stays in its list even when no card has it any more after
    a reload, so the selection never jumps.
- **Matching:** a card shows when it matches every filter in use (AND). This
  is applied after the stat card filter (2.12b) and with the search (2.14a).
  Lane counts and the foot count the cards shown. It uses the rule
  `matchesMenuFilters(emergencyCase, filters)` in `boardFormat.ts`, and
  `caseStatusLabel` for the labels.
- **State:** held in `PatientFlowBoard`, alongside its lane tabs. Choices stay
  while the page is open; they are not saved.

## Out of scope

- Choosing more than one value per filter, and saved or shared filter sets.
- Priority (2.14d).
- Filtering patients who aren't on the board (Patients, 4.6a).

## Notes for the AI

- Follow `ProfileMenu`'s open and close code (pointerdown outside, Escape
  returning focus). Don't add a menu library.
- Native `<select>`s keep keyboard and screen-reader use simple. Label each
  one.
- Sort clinician and species options alphabetically, after the fixed first
  options.
