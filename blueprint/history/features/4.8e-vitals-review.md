# Feature: Review and display the latest vitals

**From build-plan:** feature 4.8e
**Status:** complete
**Branch:** `feature/vitals-review`
**Audit:** recommended - changes a clinical form's prefilled values and new-record semantics, temperature conversion and modal dismissal.

## Goal

Staff can see all seven fields from the latest vitals set and review those
values when recording another assessment. Accidental backdrop clicks must
not close the form or lose its draft.

## Current behavior and approved decisions

- PatientOverviewPanel.tsx renders only the four numeric tiles. The API and
  client VitalsRecord already include mucousMembraneColor,
  capillaryRefillTime, mentation, recordedAt and recordedBy.
- RecordVitalsDialog.tsx opens seven blank inputs and closes when a click
  targets the dialog itself, including backdrop and empty dialog areas.
- The user chose Patient Overview improvements before the case-status API,
  and saving the full reviewed vitals form as a new timestamped set.
- The approved 2026-10-30 split is 4.8e vitals fixes, 4.8f inline pain and
  unsaved-change protection, then 4.8g prominent saved-assessment details and
  a durable change summary. This spec covers only the first part.

## In scope

- Keep the four numeric tiles and API-provided Outside range indicators.
  Under them, display labelled Mucous membrane colour, Capillary refill time
  and Mentation values from detail.vitals[0]. Missing observations say
  Not recorded; never fill gaps using an older set. Render text literally
  with wrapping, including long unbroken input.
- Add the latest set's Recorded time and recorder within the Vitals section,
  following the existing pain section's time formatting. Omit the staff
  separator/name when recordedBy is null; do not fabricate metadata when
  there is no set. The prominent cross-section placement belongs to 4.8g.
- On opening Record vitals, snapshot all seven values from the latest set
  and the target case. Missing values remain blank; with no set, all inputs
  start blank. Do not merge historical sets. Same-case background refreshes
  must not overwrite the opening snapshot or edits; reopening uses the then
  current latest set. Retain the initial heart-rate focus and patient/case
  identification.
- Prefill temperature as Celsius with one decimal place. If the submitted
  numeric Celsius value equals the opening displayed Celsius value, reuse
  the original Fahrenheit reading exactly. Otherwise apply the existing
  one-decimal Celsius validation and Fahrenheit conversion. This prevents
  an unchanged 80.0 F reading displayed as 26.7 C from becoming 80.1 F.
  Clearing the field omits it in the new set; never silently restore it.
- Explain the behavior in the form: Review all values before saving. Saving
  records the full form as a new set; clear values that were not assessed.
  Save sends every populated field, including unchanged readings, through
  the existing POST. Permit an unchanged populated form to be recorded as a
  reviewed new assessment. Trim observations; omit blank fields. Existing
  records remain immutable, and time/recorder remain server-controlled.
- Retain all current bounds: whole-number heart rate 1-400, respiratory rate
  1-200, SpO2 50-100; Celsius 26.7-46.1 with at most one decimal place and
  stored Fahrenheit 80-115; observations at most 50 characters; at least one
  reading or nonblank observation. No clinical thresholds or acuity changes.
- Remove click-to-dismiss from Record vitals. Backdrop clicks and clicks in
  empty modal space leave the dialog and draft intact. Retain deliberate
  Cancel, close-button and Escape dismissal when not saving, with focus
  restored to Record vitals. Unsaved-change confirmations are 4.8f, not a
  new dialog/navigation framework in this branch.
- Preserve the existing pending-save guard, disabled controls, single POST,
  success toast and immediate panel/board refresh without a hub echo.
  Preserve drafts and support manual retry on 400/network/server errors.
  Focus mapped invalid fields after pending controls become enabled; retain
  401/403 session handling and 404/409 unavailable-case handling. Ignore late
  responses after unmount, and never affect a different patient's panel.

## Out of scope

- Inline pain editing, case/navigation/unload guards and changes to other
  dialogs (4.8f); prominent combined assessment details and saved comparisons
  or a history UI (4.8g); case-status/stage changes (4.9a/4.9b).
- Server, database, migration, permission, endpoint or hub-message changes;
  editing/deleting historical assessments, recorder/time overrides, demo
  data changes, new dependencies and unrelated layout refactors.

## Data / contracts

- No contract or schema changes. GET /api/cases/{id} already supplies vitals
  newest first, including all observations, recordedAt and nullable recordedBy.
- Reuse POST /api/cases/{id}/vitals with optional heartRate, respiratoryRate,
  temperatureF, spO2, mucousMembraneColor, capillaryRefillTime and mentation.
  The payload is the reviewed form, not a patch. Clearing a value omits it;
  a missing value in the new set does not inherit from older records.
- Preserve 201 success; 400 field errors; 401/403 refusal; 404 missing;
  409 discharged. Existing server recording updates LastUpdated and emits
  caseUpdated with the case ID. Existing acuity and history remain intact.

## Security

- No new server surface. Existing TeamMemberPolicy protects case detail and
  vitals writes; pet parents must not reach the staff form or case endpoint.
- Bind drafts/writes to the opening case, clear them on case switch/unmount,
  and never put clinical inputs in logs, URLs, page titles or browser storage.
  Use React escaping and existing safe error messages; no raw API bodies.
- Preserve existing forced-session/refusal navigation; it must not be blocked
  by modal behavior. No token, owner-contact or clinical-value logging.
