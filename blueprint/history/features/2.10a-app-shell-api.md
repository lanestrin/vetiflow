## Goal

The top bar's profile shows an avatar with initials and a display name ("JR",
"Dr. Jordan Reed"). `GET /api/auth/me` returns what it needs, so 2.10b can
draw it.

## Design reference

`blueprint/reference/vetiflow-er-dashboard.html`, top bar: `.profile` with
`.avatar` "JR" and "Dr. Jordan Reed".

## In scope

- `GET /api/auth/me` adds `displayName`, `initials` and `role`.
- It reads the account from the database by the token's account id, so the
  profile reflects the current staff record. An account that no longer exists
  gets `401` ProblemDetails.

## Out of scope

- The shell and profile on screen (2.10b).
- Signing out deactivated accounts or revoking tokens (M3).

## Data / contracts

`GET /api/auth/me` (any signed-in account):

```json
{
  "name": "Jordan Lee",
  "experience": "teamMember",
  "displayName": "Dr. Jordan Lee",
  "initials": "JL",
  "role": "veterinarian"
}
```

- `name`: first and last name, unchanged.
- `displayName`: "Dr. " before the name for a veterinarian; the name for every
  other role and for pet parents.
- `initials`: the first letter of the first and last name, upper case.
- `role`: the `StaffRole` (`veterinarian`, `technician`, `assistant`,
  `receptionist`, `manager`) for a team member; `null` for a pet parent.
- No email, phone or other contact detail is added.

## Security

Unchanged: `[Authorize]`, any signed-in account, own profile only (by the
token's account id). Signed out or a made-up token: `401`.
