# Feature: Clinical review drawer

**From build-plan:** feature 3.6a
**Status:** complete
**Branch:** `feature/clinical-review-drawer`
**Audit:** recommended - adds a clinical-data review surface with modal focus management, live refetch behavior and patient-bound lifecycle handling.

## Goal

Staff can open a focused, read-only Clinical drawer from the selected
Patient Overview to review the latest documented vitals and assessment
findings. The drawer always belongs to the selected encounter and does not
turn entry timestamps or provisional demo flags into clinical conclusions.

## Design reference

- Requirements: `blueprint/reference/patient-overview/VETIFLOW_ER_OVERVIEW_SPECIFICATION.md`,
  sections 5.4 and 6; source mapping in the adjacent README.
- Behavioral POC: `VetiFlow_ER_Overview_Shared_Status_POC.html`, its Clinical
  quick-access drawer. This is explicitly not a pixel-perfect specification;
  use the existing application design system rather than copying its tiny
  text, hidden legacy controls, demo findings or styling values. No screenshot
  recreation is required for this item.
- Follow the app's native-dialog patterns and overviewFormat helpers, with
  readable rem-based text, 700 bold and the shared 1px focus token. At desktop
  widths use a right-edge drawer treatment; narrow viewports get a usable
  viewport-fitting surface with independently scrollable content and a
  reachable close control. No new dependency or animation is required.

## In scope

- Add one enabled **Clinical** quick-access button inside Patient Overview
  after the Vitals section, only while an authorized case detail is loaded.
  Its opening context comes from that actual detail, never a prototype lookup
  or a second patient-name map. No-selection, initial loading, failed and
  not-found states do not offer a trigger. An already loaded discharged case
  can still be reviewed read-only if the existing API permits its detail.
- Open a labelled native modal dialog styled as a drawer, titled **Clinical**
  and identified by patient name and case number. It contains no editing,
  recording, signing or task-completion controls. Only one review drawer is
  open; add only Clinical now. Timeline/Medications follow separately and
  will use the same single-open review control, not concurrent overlays.
- Display four labelled latest-set values: Heart rate (bpm), Respiratory rate
  (/min), Temperature (Celsius, one decimal using temperatureLabel) and SpO2
  (%). Missing readings show **Not recorded**, including a record with only
  observations. With no set, state **No vitals recorded** and show the numeric
  missing states without inventing a timestamp or recorder.
- Render numeric values neutrally. Do not copy outOfRange flag styling,
  Outside range labels or clinical threshold calculations into the new
  drawer. Validated alerts are 4.14; the compact Overview cutover is 2.23.
- Under **Clinical assessment**, show the latest set's nonblank documented
  Mucous membrane colour, Capillary refill time and Mentation as labelled
  literal text. Omit absent finding rows; if none are documented, say
  **No assessment findings recorded in this set** (or **No assessment findings
  recorded** when there is no set). Do not borrow older findings or readings.
  Explicit text such as Not assessed remains literal, never normal/negative.
- For a set, show **Entered [formatted recordedAt]**, with recorder name when
  present; omit the separator/name for null recordedBy. Explain **Measurement
  time is not available in this record**. Never label recordedAt as measured
  time or invent age/freshness warnings. Use timeLabel so non-today records
  include their date. Do not use EmergencyCase.lastUpdated as assessment time.
- Use only current detail.vitals[0]. There is no history browser, cross-set
  merge, generic pain assessment, raw triage/intake note display, fabricated
  exam narrative, hydration/pulse-quality placeholder or approved-note claim.
- Initial focus goes to the drawer's Close control. Support keyboard use,
  native modal focus containment, Escape and a clearly labelled close action.
  Ignore backdrop/empty-space clicks, consistent with the requested less
  accidental dismissal. Normal close restores focus to Clinical when it
  still exists; if a detail error removed the trigger, use the current Patient
  Overview heading as a fallback. Never refocus a departed page/old patient.
- Close and clear the review state on patient change, deselection, unavailable
  detail, session refusal/navigation or unmount. No old patient content may
  remain visible during the new patient's load or reappear after a retry.
  Late effects/close events must not close another patient's newly opened
  view or steal its focus. Do not create a second data-fetch path or loading
  cache for the drawer.
- A successful same-case refetch keeps the drawer open and updates it from
  the current detail without resetting focus. Unlike an editable form, the
  review does not freeze the opening values. Existing board/hub refresh and
  Record vitals save readback feed the same detail source. If the current
  loader changes to failed/not-found, close the drawer and keep the existing
  parent error/retry state; do not display unlabelled cached clinical data.
- Keep existing overview content and entry workflows intact for this first
  incremental feature. Moving/removing inline observations, pain, chronology
  and task controls belongs to 2.23 and its approved entry-workflow cutover.

## Data / contracts

- Reuse GET /api/cases/{id}; no new endpoint, entity, column, index, enum,
  migration, setting or hub event. Vitals order remains newest first.
- Existing recordedAt/recordedBy are entry metadata, not measured time.
  Optional numbers/observations stay missing when absent in the latest set.
- Existing 401/403 handling and getCase's 404/null behavior remain the parent
  loader's responsibility. The drawer receives the current CaseDetail and
  performs no independent fetch, mutation or automatic retry.

## Security

- Current staff demo authorization only: the existing case API requires
  TeamMemberPolicy and the staff route guard excludes pet parents. Do not
  claim new role/credential or field-level protection; S.6/3.7 remain separate.
- Read only the selected encounter's actual response. No clinical values in
  logs, analytics, page titles, URLs or browser storage; no raw error bodies.
  Render findings and staff names with React escaping. Do not add raw intake
  notes, owner contacts or prototype clinical text to the drawer.
- Auth refusal/navigation clears the review surface. Cleanup never retains
  another patient's detail or returns focus to a disconnected private view.

## Testing and check strategy

- Client: ClinicalReviewDrawer.test.tsx, PatientOverviewPanel.test.tsx and
  ErBoardPage.test.tsx with Vitest, Testing Library, MSW and the fake hub.
  Query by role/label/text, not private CSS classes; do not test CSS values.
  Include explicit missing/zero distinctions, observation text containing
  markup, an older populated set behind a partial newest set, a non-today
  entry timestamp and null recorder. Tests must prove no fabricated measured
  time, imported demo map, write request or extra case-detail fetch.
- Await focus effects rather than assuming an error/close render has already
  moved focus. Reuse native-dialog shims for jsdom; document their limits.
- Server: no new tests planned; no server behavior changes. Existing case
  detail/access tests remain the source of API authorization coverage.
- Automated integration validates readback/cleanup and existing UI regressions.
  Visual/native-browser /check is deferred by the user's explicit preference.
  Implement for 320 CSS px, enlarged text, reachable close controls, visible
  1px keyboard focus, forced colours and reduced motion without claiming
  unobserved visual/accessibility results.
