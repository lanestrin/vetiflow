## Goal

Staff complete triage on an incoming case, and re-triage a case later, from
the patient overview panel. The case's card, lane and panel update on every
open board, using the 4.2a endpoint (`POST /api/cases/{id}/triage`).

## Design reference

`blueprint/reference/vetiflow-er-dashboard.html`:

- `#triageAction` "✓ Complete triage" in `.detailactions` (amber
  `.triage-action`, first of the three buttons), shown only while the case is
  in stage Incoming.
- After it: the card leaves "New" and "<priority> · provisional", the panel
  hides the button, the timeline gains "Triage completed", and the toast
  "<name> triage completed".
- `#more` (**•••**, `.toolbtn`) in the panel header.

The prototype completes triage in one click and has no re-triage screen; the
dialog below follows the intake dialog's look (4.1b).

## Decisions taken for this item (recommended defaults)

- **Complete triage opens a short dialog**, preset to the provisional
  priority, so one more press confirms it and a clinician can still change it
  (4.2a: "confirm or change the provisional priority"). Optional triage notes.
- **Re-triage** is the one item in the **•••** menu for a case past Incoming.
  For an incoming case **•••** stays disabled (Complete triage covers it);
  assignment joins the menu in 4.3b.
- **Who:** any team member, as the 4.2a endpoint allows until roles exist (S.6).
- **Card wording is unchanged:** after triage the card shows the server's wait
  chip (STAT, or minutes) and "Triage · N min". The prototype's "Triage
  complete · awaiting assignment" foot is not adopted.

## In scope

- **Service:** `triageCase(caseId, { priority, notes })` in `casesApi.ts`.
  `204` resolves; `400` → `FormRejectedError`; `404` → `CaseGoneError` ("not
  found"); `409` → `CaseGoneError` ("discharged"); `401`/`403` as elsewhere;
  other → an error.
- **TriageDialog** (native modal `<dialog>`, as the intake dialog):
  - Title "Complete triage" or "Re-triage"; the patient name and case number
    under it.
  - "Priority" radio group (Critical, Urgent, Stable), preset to the case's
    current acuity; "Triage notes" (optional, up to 2000 characters, counted
    by `maxLength`).
  - Buttons: Cancel and "Complete triage" / "Save priority"; the confirm
    button says "Saving…" and is disabled while the request runs.
  - Focus on the first radio when opened; Escape, Cancel and the backdrop
    close it; focus returns to the button that opened it.
  - Errors in the dialog, nothing typed lost: field message from a `400`;
    "This case is no longer on the board." (`404`); "This case has been
    discharged." (`409`); "Unable to save triage. Try again." (other).
    `401` and `403` leave the page as the board does.
- **Panel:**
  - **✓ Complete triage** (amber, darkened for AA) first in the actions row,
    only for a case in stage Incoming.
  - **•••** opens a small menu (disclosure button with `aria-expanded`) with
    **Re-triage** for a case past Incoming. Escape or a click outside closes
    it; Escape returns focus to **•••**.
- **After saving:** the dialog closes, the toast says "<name> triage
  completed" or "<name> re-triaged · <Priority>", and the board reloads at
  once (the panel reloads with it). Other boards reload from the hub's
  `caseUpdated`, as today.

## Out of scope

- Assignment and other **•••** items (4.3b); the stat cards' triage count
  (2.12b); the Incoming filter (2.14); role checks (S.6).
- Any server change: 4.2a's endpoint, rules and timeline wording stay as they
  are.

## Data / contracts

- No API change. The client sends `POST /api/cases/{id}/triage` with
  `{ "priority": "critical" | "urgent" | "stable", "notes": string | null }`
  and reads `204`, `400` (`errors.Priority`, `errors.Notes`), `401`, `403`,
  `404`, `409` as 4.2a defines them.
- Hub: unchanged; `caseUpdated` with the case id reloads other boards.

## Security

- No new surface. The endpoint stays team members only; the dialog follows
  the board's handling of `401` and `403`.
- Triage notes are clinical: never logged to the console, never in the toast.
- Acuity changes only through the endpoint (which uses `RecordTriage`); the
  client never sets it locally.
