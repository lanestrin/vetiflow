## Goal

The board's **Priority** button switches every lane between priority order
(the default) and longest in current stage first. With it pressed, a case
stuck in one stage moves to the top of its lane.

## Design reference

`blueprint/reference/vetiflow-er-dashboard.html` has the button after Filter:
`<button class="toolbtn" id="sort">↕ <span>Priority</span></button>`.
Pressing it only toasts "Patients sorted by clinical priority", so the
behaviour below is a proposal, and approving this spec approves it:

```
 Patient flow                    [⇣ Incoming 1] [⚑ Filter] [↕ Priority]
 Updated just now · 10 active cases                         ^ navy while pressed

 Urgent lane, default (API order: by arrival)   Pressed (longest in stage)
   Biscuit  34 min   Treatment · 5 min           Mochi    22 min   Diagnostics · 20 min
   Mochi    22 min   Diagnostics · 20 min        Biscuit  34 min   Treatment · 5 min
```

- **The button:** a `.toolButton` like Incoming and Filter, with "↕ Priority".
  It is navy with white text while pressed, and the label hides at 650px, as
  the others' do.

## In scope

- **Why stage time:** within a lane all cards share an acuity, and
  `GET /api/cases` already orders by acuity, then arrival
  (`GetCases_OrdersByAcuityThenLongestWait`). Priority order and "longest
  since arrival" are therefore the same order. The second order uses minutes
  in the current stage instead (decided 2026-10-29 while writing this spec):
  the "Treatment · 5 min" figure each card already shows.
- **Default (not pressed):** the API's order, as today.
- **Pressed:** in every lane, the earliest `stageEnteredAt` comes first. Ties
  keep the API order. The rule is `sortByLongestInStage(cases)` in
  `boardFormat.ts`. It returns a new array and never sorts the cases it is
  given.
- **With the other tools:** the sort works on the cards the stat card
  filter, Filter menu and search leave, so the lane counts and foot don't
  change. It applies to the Not triaged lane too. Live reloads keep the chosen
  order, and the selected card stays selected.
- **The button's state:** `aria-pressed` (true while longest in stage is
  on) and the accessible name "Priority, longest in stage first", which keeps
  the visible word "Priority" in it. The state lives in `PatientFlowBoard` next
  to the Filter menu's choices. It stays while the page is open and is not
  saved.

## Out of scope

- Any server change. The list endpoint's order stays as it is.
- More sort orders, or a sort menu.
- A toast on pressing it. The pressed state and the card order show the change.
- Saving the choice between visits.

## Notes for the AI

- Sort the shown cases once, before they are split into lanes. It gives the
  same result per lane and keeps the lane code unchanged.
- `Array.prototype.toSorted` or a copied `sort`: the sort is stable, so ties
  keep the API order without a second key.
- Compare times with `new Date(...).getTime()`, as `minutesSince` does, not
  string comparison.
