# Feature: What changed since the previous saved vitals

**From build-plan:** feature 4.8g
**Status:** complete
**Branch:** `feature/assessment-change-summary`
**Audit:** recommended - new client logic that states how clinical readings changed; worth checking it never misstates a missing value as unchanged or implies a clinical judgement.

## Goal

Staff reviewing a case can see, for each saved vitals set, what differs from the
set saved before it: which readings changed and from what, which stayed the same,
and which were not recorded this time. It lives in the Clinical and Timeline
review drawers, not the compact Patient Overview, and it states facts only: no
"improved", "worse", arrows or colours.

## Design reference

- `blueprint/reference/patient-overview/README.md`, row "Saved changes and
  attribution": a persistent comparison in deeper review, using saved records
  and truthful event/entry times, without turning the compact panel into a ledger.

## In scope

- A pure helper `vitalsChanges(current, previous)` in
  `components/overview/vitalsChanges.ts` that compares two saved `VitalsRecord`s
  field by field (heart rate, respiratory rate, temperature, SpO₂, mucous
  membrane colour, capillary refill time, mentation) and returns, in that order:
  - **changed**: both recorded and different ("Heart rate 160 → 148 bpm");
  - **newly recorded**: recorded now, not in the previous set ("SpO₂ 97%, not
    recorded in the previous set");
  - **not recorded this time**: in the previous set, missing now ("Temperature
    not recorded in this set; previous set 39.4 °C");
  - **unchanged**: both recorded and equal, listed together ("Unchanged: Resp
    rate 48 /min, Mentation Alert").
  Readings missing from both sets are left out. Text findings compare after
  trimming; a blank text counts as not recorded. Values use the drawers'
  existing labels and units (`temperatureLabel` for temperature).
- **Previous set** means the set saved just before it (the next older entry in
  `detail.vitals`, which the API orders by entry time). Each summary names it:
  "Compared with the set entered <time>", so an out-of-order measurement time
  is never hidden.
- **Timeline drawer:** each "Vitals recorded" row shows its change summary under
  its times; the oldest set shows "First vitals saved for this case".
- **Clinical drawer:** under "Latest recorded vitals", a "Since the previous
  saved set" section for the latest set, or "No earlier vitals saved for this
  case" when it is the only one.
- Plain text, a description list per summary; no icons, arrows other than the
  "from → to" text, or colour coding.

## Out of scope

- Triage: its timeline events already state the change ("Re-triaged · Urgent →
  Critical" or "· confirmed").
- Pain scores: legacy records, no longer recorded or shown (Decisions, "Pain
  records and placement"); no comparison that would present them as a scale.
- Any server change; any change to the compact Patient Overview; alerts or
  thresholds (4.14a/b); measurement-time ordering rules beyond naming the
  compared set.

## Notes for the AI

- Keep the wording factual: never "improved", "worse", "up", "down", or colour.
- Compare the displayed values (the same label helpers on both sides), so two
  stored temperatures that show the same never read as a change.
- Reuse the drawers' existing styles where they fit; no new component library.

## Open questions

None blocking. Choices made: vitals only (triage already states its change;
pain is legacy); "previous" is the previous saved set by entry time, named on
screen.
