## Goal

`GET /api/cases` returns everything a patient flow card in the prototype
shows, so 2.11b can draw the acuity lanes and cards without more calls.

## Design reference

`blueprint/reference/vetiflow-er-dashboard.html`, `.patient` cards: name;
"Dog · Golden Retriever · 8y"; the wait chip (STAT, 18 min, Ready, Recheck);
"Avery Chen · Hit by vehicle"; "In treatment · 12 min"; "JR Reed". The detail
panel's location row ("Treatment · Oxygen cage"). No screen change here.

## In scope

Each board list item adds:

- **Patient date of birth**, so the card can show the age ("8y"). The age is
  worked out on screen (2.11b), so it never goes stale.
- **Owner name** ("Avery Chen"), or null when the patient has no owner. No
  phone or email.
- **Room type** next to the room name, for the location ("Treatment · Oxygen
  Cage").
- **Stage entered at:** when the case moved into its current stage. The card
  counts minutes from it on screen.
- **Wait chip**, by the 2026-10-28 decision, first match wins: Critical acuity
  → `stat`; status ready for next step → `ready`; stage Recheck → `recheck`;
  not triaged → `new`; otherwise `minutes` (the screen counts minutes since
  arrival).
- **Clinician:** the assigned doctor, or the technician when no doctor is
  assigned, as a short name (last name, "Reed") and initials ("JR"); null when
  neither is assigned.

To support the stage time:

- `EmergencyCase.StageEnteredAt`, set through a new `MoveToStage` method that
  changes it only when the stage really changes. `PATCH /api/cases/{id}/stage`
  uses it.
- A migration adds the column and fills existing cases with their arrival
  time (the best time stored).
- The demo seed sets realistic stage times and dates of birth, and the demo
  time refresh (#62) shifts stage times with the rest.

## Out of scope

- The cards, lanes and on-screen minutes (2.11b).
- A timeline event for stage changes and the rules for which moves are
  allowed (4.9a, **Update status**).
- Clinical tags on cards (4.4), care team assignment (4.10).

## Data / contracts

- **Column** `EmergencyCases.StageEnteredAt timestamptz NOT NULL`. Migration
  `AddStageEnteredAt`: add it, set it to `ArrivalTime` for existing rows.
  Down: drop it.
- **Domain:** `EmergencyCase.MoveToStage(CaseStage stage)`: when the stage
  differs, sets `Stage`, `StageEnteredAt` and `LastUpdated` to now; when it is
  the same, changes nothing. A new case's `StageEnteredAt` is its arrival
  time.
- **Enum** `WaitChip { Stat, Ready, Recheck, New, Minutes }`, JSON
  `"stat" | "ready" | "recheck" | "new" | "minutes"`.
- **Board list item** gains:

  ```json
  {
    "patientDateOfBirth": "2018-04-02",
    "ownerName": "Avery Chen",
    "room": { "id": "…", "name": "Oxygen Cage", "type": "oxygen" },
    "stageEnteredAt": "2026-10-28T10:53:00Z",
    "waitChip": "stat",
    "clinician": { "id": "…", "shortName": "Reed", "initials": "JR" }
  }
  ```

  `patientDateOfBirth`, `ownerName`, `room` and `clinician` may be null.
  `room` keeps `id` and `name`, so the current board still works. The case
  detail (3.1) is unchanged.

## Security

No new endpoint. `GET /api/cases` stays team members only (401 signed out,
403 for a pet parent). The owner's name is added for staff; phone and email
are not. The hub still sends only the case id.
