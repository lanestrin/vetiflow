## Goal

`GET /api/cases/{id}` returns everything the prototype's patient overview
panel (3.2b) shows that is already stored, so the panel needs no other call.

## Design reference

`blueprint/reference/vetiflow-er-dashboard.html`, `aside.detail`: "Case ER-2481
· Checked in 10:42 AM", **•••**, species avatar, name, "Dog · Golden Retriever
· 8 years · 31.4 kg", the acuity badge, the pet parent bar (name, Call,
Message), the vitals tiles, the pain score, "Location: Treatment · Oxygen
cage", "Next reassessment", "Client update", the care timeline, Next actions,
and **Complete triage** for incoming cases.

## What the detail already has, and what is missing

| Panel shows | Today | 3.2a |
| --- | --- | --- |
| Case number, check-in time | `caseNumber`, `arrivalTime` | - |
| Name, species, breed, weight, acuity | yes | - |
| Age | `patient.dateOfBirth` | adds `patient.dateOfBirthIsEstimated` |
| Pet parent and phone | `owner` | - |
| Vitals, timeline, tasks | yes | - |
| Location "Treatment · Oxygen cage" | `stage`, `room` (id and name only) | `room` adds `type` (the area), like the board list |
| Minutes in stage | no | adds `stageEnteredAt` |
| Complete triage shown for incoming | `stage` | - |
| Next reassessment, Client update | no | **not here**: 4.4a returns them (due items are tasks, decided 2026-10-28) |
| Pain score | no | **not here**: 4.8a |

The intake fields stored by 4.1a are returned nowhere yet. The detail adds
them, so staff can check allergies and medications on the next visit (the
2026-10-28 decision): `patient.allergies`, `patient.currentMedications`,
`allergiesAtIntake`, `medicationsAtIntake`, `treatmentAuthorization`,
`referringClinic`.

## Decisions taken for this item (recommended defaults)

- Next reassessment and client update come from 4.4a, not 3.2a; the build plan's
  3.2a line is updated to say so.
- The intake fields are added here (read-only) rather than waiting for a later
  item, since the detail is the one place staff read a case.

## In scope

- The fields above in `CaseDetailDto` and `CasePatientDto`; `room` becomes
  `CaseRoomDto` (`id`, `name`, `type`).

## Out of scope

- The panel itself (3.2b), due items (4.4a), pain score (4.8a), any writes.

## Data / contracts

- `CaseDetailDto` adds `stageEnteredAt` (time), `allergiesAtIntake`,
  `medicationsAtIntake`, `referringClinic` (text or null),
  `treatmentAuthorization` (`notDiscussed` | `pending` | `authorized` |
  `declined`); `room` is `{ id, name, type }` or null.
- `CasePatientDto` adds `dateOfBirthIsEstimated` (bool), `allergies`,
  `currentMedications` (text or null).
- No client code reads the case detail yet, so changing `room` breaks nothing.
- No migration.

## Security

- Unchanged: team members only (401 signed out, 403 pet parent). Allergies,
  medications and referral are clinical: never logged; the detail is never
  sent on the hub.
