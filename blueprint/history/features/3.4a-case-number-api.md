## Goal

Staff refer to a case by a short human number, as the prototype does
("Case ER-2481"), instead of its id. Every case gets one when it is created,
and existing cases are numbered in the order they arrived.

## Design reference

`blueprint/reference/vetiflow-er-dashboard.html`: the cards' `data-id`
("ER-2481", "ER-2479", …) and the detail panel's "Case ER-2481". Shown on
screen by 2.11b and 3.2b; no screen change here.

## In scope

- `EmergencyCase.CaseNumber` (int), filled by the database from a sequence on
  insert, unique.
- A migration that creates the sequence, adds the column, numbers existing
  cases by arrival time, moves the sequence past the highest number, and lets
  the app role use the sequence.
- `GET /api/cases` and `GET /api/cases/{id}` return `caseNumber`.

## Out of scope

- Showing the number (2.11b, 3.2b); searching by number (later, with 2.14).

## Data / contracts

- **Sequence** `CaseNumbers`, starting at 2401 (so demo numbers look like the
  prototype's ER-24xx).
- **Column** `EmergencyCases.CaseNumber integer NOT NULL DEFAULT
  nextval('"CaseNumbers"')`, unique index `IX_EmergencyCases_CaseNumber`.
  The application never sets it.
- **Migration** `AddCaseNumbers`:
  - Up: create the sequence; add the column; renumber existing rows 2401… by
    `ArrivalTime`, then `Id`; `setval` the sequence to the highest number (or
    2400 when there are none); the unique index; `GRANT USAGE ON SEQUENCE` to
    `vetiflow_app`.
  - Down: drop the index, the column and the sequence.
- **JSON:** `caseNumber: "ER-2481"` on the board list items and the case
  detail. Later items keep the "ER-" prefix and the number.

## Security

No new endpoint; both endpoints stay team members only. The number is not
personal data. The app role gets `USAGE` on the one sequence, nothing more.
