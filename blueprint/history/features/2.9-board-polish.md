## Goal

The board reads correctly to screen readers and in the browser tab: one
heading level per layer, a real page title and icon, and no page offered to
search engines. These are small fixes stakeholders notice at once [25, 26].

## Design reference

- Favicon: the brand mark from `blueprint/reference/vetiflow-login-mock.html`
  (a "+" in teal `#126b65` on mint `#e1f3ed`, rounded square).

## In scope

- **Heading levels:** the page title is `h1`, each lane title `h2`, and a
  patient name on a card becomes `h3` (today both lanes and cards are `h2`,
  so a screen reader's heading list is flat).
- **Page title:** `index.html` says `VetiFlow` (today `vetiflow.client`), and
  the board sets `ER Board · VetiFlow` with React 19's `<title>` element, so
  later pages (sign-in, pet parent) set their own.
- **Favicon:** `index.html` already links `/favicon.svg`, but the file does
  not exist (there is no `public/` folder), so every load gets a 404. Add
  `vetiflow.client/public/favicon.svg` with the mockup's mark.
- **No search engines:** `<meta name="robots" content="noindex, nofollow">`
  in `index.html` and `public/robots.txt` with `Disallow: /`. Vercel serves
  files from `public/` before its catch-all rewrite to `index.html`.
- **Build plan:** move "don't count discharged patients" from 2.9 to 2.3 (see
  Notes).

## Out of scope

- Which cases the board shows, and so the counts (2.3: active cases only).
- `X-Robots-Tag` headers on Vercel and the API (8.2).
- The app shell, top bar and card restyle (2.10, 2.11).

## Notes for the AI

- Query headings with `getByRole('heading', { level: 3, name })`.
- Keep the SCSS class on the card name so its look doesn't change; only the
  element changes.
- **Why the count moves to 2.3:** the list DTO has no discharge time and
  `GET /api/cases` returns every case, so the client can't tell a discharged
  case from an active one. 2.3 filters the list to active cases on the
  server, and then the "Patients in ER" count is right without client logic.
  Doing it here would mean adding a field 2.3 makes unnecessary.
