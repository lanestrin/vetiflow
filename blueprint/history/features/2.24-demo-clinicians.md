# Feature: More clinicians in the demo clinic

**From build-plan:** feature 2.24
**Status:** complete
**Branch:** `feature/demo-clinicians`
**Audit:** recommended - the startup seeder changes rows in already-seeded databases, including the deployed demo; worth checking it only ever touches its own demo fixtures.

## Goal

The demo clinic has two veterinarians and two technicians, and every one of the
fifteen extra demo cases goes to the first of each by last name (Jordan Lee and
Alex Kim), so a "My Patients" view would show one doctor with everything. To
prepare for the veterinarian and technician My Patients workspaces (2.22a-d,
`blueprint/reference/vet-my-patient/`), the demo clinic gets four veterinarians
and four technicians, with the demo cases spread across them.

## Approved choices (2026-11-02)

- Four veterinarians (Jordan Lee, Priya Shah and two new) and four technicians
  (Sam Ortiz, Alex Kim and two new).
- One team sign-in stays: `team@vetiflow.demo` is Jordan Lee. No new accounts.
- Cases rotate across the clinicians; incoming cases stay unassigned, as today,
  so the shared pool and "Unassigned" still show.
- 4.13a stays blocked on the Action selection decision; this item comes first.

## In scope

- **New demo staff**, fictional, with fixed demo IDs (`DemoFixtureId(4, n)`) so
  they are added once and recognised later:
  - veterinarians **Elena Novak** (Available) and **Marcus Bell** (Busy);
  - technicians **Riley Chen** (Available) and **Dana Price** (Busy).
- **`SeedDemoStaffAsync`**, run on every startup before the extra cases: adds any
  of the four that are missing; never changes existing staff.
- **Rotation for new seeds:** `SeedAdditionalCasesAsync` gives each non-incoming
  case the veterinarian and technician at `seed.Index` modulo the active
  veterinarians and technicians, ordered by last name then first name. The
  case's triage, vitals, pain score, triage event and task use that case's
  veterinarian as the recorder and its technician as the task assignee, as
  today with the single doctor.
- **Existing demo databases** (local and deployed, seeded before this item): a
  startup step `SpreadDemoAssignmentsAsync` reassigns the extra demo cases (the
  fixture case IDs only, active ones only) by the same rotation, but only while
  every assigned one of them still shares a single veterinarian. Once spread,
  that condition is false, so it never runs again or overrides a reassignment
  made in the app. It changes only `AssignedDoctorId` and `AssignedTechnicianId`;
  historical recorders and timeline actors stay as they were.
- The original three hand-written demo cases (Buddy, Luna, Max) are unchanged.

## Out of scope

- Sign-ins for the new staff; role-based access (S.5/S.6); My Patients itself (2.22a-d).
- Assignment writes or rules (4.3a); action priority (4.13a, blocked).
- Real-data behaviour: none of this runs unless demo seeding is enabled.
