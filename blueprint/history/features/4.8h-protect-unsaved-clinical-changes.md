# Feature: Protect unsaved clinical changes

**From build-plan:** feature 4.8h
**Status:** complete
**Branch:** `feature/clinical-unsaved-changes`
**Audit:** recommended - protects private clinical input across patient/navigation changes while preserving forced authorization exits.

## Goal

Staff can keep editing unsaved encounter documentation instead of losing it
when a form closes, selection changes or navigation occurs. Retain the compact
Overview and entry locations delivered in 2.23.

## Design reference

Keep the current Overview and its More actions/task-view entry points aligned
with `blueprint/reference/patient-overview/VetiFlow_ER_Overview_Next_Care_Action.html`.
Use the existing native-dialog styling and focus conventions for one shared
discard confirmation; no overview redesign or screenshot recreation.

## In scope

- Protect Record vitals, complete/re-triage, Add task/blocker, and Set
  reassessment/client update. Read-only review drawers have no dirty state.
- Compare editable field values with their opening baseline. Prefilled values
  alone are clean; editing and restoring the baseline clears dirty state.
  Loading options, validation messages and disabled controls must not create edits.
- Dirty Close, Cancel, Escape and any supported backdrop dismissal offer
  **Keep editing** and **Discard changes**. Default focus and Escape keep
  editing; returning from confirmation restores form focus. Clean dismissal
  needs no confirmation. Preserve vitals' existing ignored-backdrop behavior.
- Guard intentional patient switches/deselection, internal navigation, browser
  back/forward and explicit sign-out before changing selection, route or token.
  Staying preserves the original form and selection. Discard permits the
  intended action once, without duplicate prompts. Do not warn for changes
  that leave the form mounted and its draft intact.
- Use the supported native unload warning for refresh/tab close when dirty;
  browsers control its wording and may suppress it without user interaction.
- Preserve input and errors through failed saves and same-case refreshes.
  Background load failure or a case leaving the board must not silently unmount
  a dirty form. Keep its original encounter context and show unavailable state
  when appropriate; do not allow invalid writes to departed/missing cases.
- While saving, prevent duplicate submissions and intentional dismissal/exit.
  Successful save clears the guard. Bind every request to the encounter captured
  when the form opened; late completions must not alter another patient's UI.
- Forced session expiry or access refusal bypasses discard prompts and clears
  private drafts and any confirmation immediately. Retain existing 401/403
  destinations and token handling; a discard guard never grants continued access.

## Out of scope

Server-persisted drafts, autosave, offline/cross-session recovery and edit
conflicts (4.15a/b); browser storage of clinical text; generic pain UI; new
clinical workflows, endpoints, fields or permissions. Intake and settings forms
are outside this encounter-form change. Existing immediate task toggles retain
their save/error behavior rather than becoming draft forms.

## Data / contracts and security

No server, schema, migration, API or hub changes. Keep field validation and
authorization authoritative on the server. Drafts stay in component memory;
clear them on authorized discard/save or forced exit. Never log or persist
clinical values in localStorage/sessionStorage. Do not label memory retention
as saved documentation, recovery or clinical signing.

## Testing

Add focused guard/confirmation tests and extend the four form suites, panel/
board selection tests and router/auth tests. Use the existing builders and MSW;
no live database is needed. Confirm a failed save retains exact input, a
same-case refresh does not reinitialize it, and restoring original values stops
the warning. Verify both ordinary navigation and forced refusal explicitly.

Run client lint, build and tests during implementation; no additional workflow
checks or planning-time test runs. Use UI-only fictional fixtures for `/check`.

## Open questions

None. This is loss prevention for the retained forms, not durable draft storage.

## Implementation notes

- Shared in-memory draft tracking and native discard confirmation protect the four retained forms. Editing back to the opening values clears the warning.
- A data-router bootstrap enables supported link/back/forward blocking without replacing the existing route tree. Patient selection and sign-out ask before changing selection or the token.
- Background refresh failures retain open forms; missing or departed encounters disable their save action. Forced refusal clears forms and confirmations and bypasses navigation blocking.
