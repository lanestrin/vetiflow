## Goal

The board summary also returns what the page heading needs (2.15b): the
clinic's name for the eyebrow ("Northside Veterinary Emergency") and the
number of clinicians on the floor for the live shift chip ("Day shift · 4
clinicians on floor"). The shift itself is already there (2.12a).

## In scope

- **The clinic's name:** a new required setting `Clinic:Name`, read once at
  startup like the shift settings. A missing or blank value stops startup with
  a message naming the setting. `appsettings.json` sets it to the prototype's
  "Northside Veterinary Emergency". Settings (9.3) takes it over later.
- **Clinicians on floor:** the count of active veterinarians and technicians
  whose status is not Unavailable. This is exactly the set
  `GET /api/staff/on-floor` lists (2.21a), so both use one shared rule.
- **Where it goes:** two new fields on `GET /api/board/summary`, so the
  heading refreshes with the stat cards (the board reloads the summary on
  every hub update). There is no new endpoint.

## Out of scope

- The heading itself: eyebrow, title, shift chip and New intake (2.15b).
- Live updates when someone changes their status. The count refreshes with
  the next board reload, and no status hub message exists yet (2.21a).
- "Last shift" figures (2.16a), and editing the name in Settings (9.3).

  later items read the name from `ClinicProfile`.
- **`GET /api/board/summary`** adds:
  - `clinicName` (string);

  Existing fields don't change. Access stays team members only: 401 signed

- No model change and no migration. No hub messages.

## Security

  of clinicians, never their names.
- The clinic's name is configuration, not a secret, so it is safe in
  `appsettings.json`.
