## Goal

CI runs `scripts/verify.ps1`, the same command you and Claude run, so "Verify
passed" means the same thing locally and on a PR, and the two can never drift
apart. This is slice C of the agreed workflow-hardening plan. The extras agreed
for slice C go in too: a PR title check, action SHA pins with Dependabot to keep
them current, and job timeouts.

## In scope

- Make the workflow tests pass under `pwsh` on Linux. That includes F-28
  (`scripts/tests/verify-evidence.tests.ps1` calls `cmd /c`) and any other
  Linux break the workflow tests show.
- `.github/workflows/ci.yml`: the two jobs keep their names ("Server tests",
  "Client lint, build and tests") and call `verify.ps1 -ServerOnly` and
  `verify.ps1 -ClientOnly`. They upload `.verify/logs` when a step fails and
  have `timeout-minutes`.
- Every `uses:` in `.github/workflows/` pinned to a full commit SHA with a
  `# vN` comment, and `.github/dependabot.yml` for the `github-actions`
  ecosystem so Dependabot keeps those pins current.
- A PR title check: `scripts/check-pr-title.ps1` plus
  `.github/workflows/pr-title.yml`. It enforces the subject rules in
  `coding-standards.md` ("Commit messages and PRs").
- Workflow tests that hold these rules in place (see Testing).
- `coding-standards.md`: the Merging section lists the new "PR title" check
  among the required checks and says CI runs `verify.ps1`.

## Out of scope

- Resolving open npm alerts, and Dependabot for npm or NuGet (1.4).

- [x] **Step 1 - Workflow tests run on Linux** - replace the two `cmd /c`
  checks in `verify-evidence.tests.ps1` with portable ones: the current
  PowerShell executable with `-Command`, writing to stderr through
  `[Console]::Error.WriteLine`. Then run every `scripts/tests/*.tests.ps1`
  under `pwsh` in a Linux container and fix, in the workflow scripts and tests
  only, whatever else fails there. Windows behaviour stays the same. *Done
  when:* the Verify "Workflow tests" step passes on Windows, and the same tests
  pass under `pwsh` in a Linux container (`mcr.microsoft.com/dotnet/sdk:10.0`
  with Node installed) run on a copy of the tracked files.
  *Found and fixed:* `scripts/db-target.ps1` did not remove competing
  connection-string variables on Linux. PowerShell passes `$null` to a .NET
  string parameter as `""`, which Windows treats as remove and Linux keeps as an
  empty variable. It now passes `[NullString]::Value`, both when removing and
  when restoring. The existing "removes competing variables" checks caught it
  on Linux.
- [x] **Step 2 - CI calls Verify** - rewrite `ci.yml` so the server job runs
  `pwsh -File scripts/verify.ps1 -ServerOnly` and the client job runs
  `pwsh -File scripts/verify.ps1 -ClientOnly`, after the same SDK and Node
  setup (npm cache kept). On failure each job uploads `.verify/logs` as an
  artifact. Each job gets `timeout-minutes` (server 20, client 15). The
  coverage steps go. Add `scripts/tests/ci-workflow.tests.ps1`. *Done when:*
  the new tests pass in Verify: both jobs call `verify.ps1` with their mode and
  never `-ReuseIfCurrent`, the two job names are unchanged, and every job has
  `timeout-minutes`.
- [x] **Step 3 - Pinned actions and Dependabot** - pin every `uses:` in
  `.github/workflows/` to the full 40-character commit SHA of its current tag,
  looked up with `git ls-remote`, with a `# vN` comment. Add
  `.github/dependabot.yml`: `github-actions` ecosystem, weekly, commit-message
  prefix `chore`. *Done when:* a test in `ci-workflow.tests.ps1` fails for any
  `uses:` that is not a 40-hex SHA and passes for the real files, and
  `dependabot.yml` names the `github-actions` ecosystem.
- [x] **Step 4 - PR title check** - `scripts/check-pr-title.ps1 -Title <t>`
  exits 0 when the title matches `<type>[!]: <summary>`. The type is `feat`,
  `fix`, `chore`, `docs` or `test`, the whole title is at most 72 characters
  and it has no trailing full stop. Otherwise it exits 1 and prints the rule
  that failed. `.github/workflows/pr-title.yml` runs it on `pull_request`
  types `opened`, `edited`, `reopened` and `synchronize`, as job "PR title",
  with `timeout-minutes: 5`. The title reaches the script through an `env:`
  variable and is never written into the `run:` text. *Done when:*
  `scripts/tests/pr-title.tests.ps1` passes for valid titles
  (`feat: add owners (0.2)`, `fix!: reject numeric stages`) and rejects bad
  ones (no type, unknown type, `Feature/owner`, over 72 characters, trailing
  full stop, missing space after the colon). A `ci-workflow.tests.ps1` check
  confirms `pr-title.yml` contains no `${{ github.event.pull_request.title }}`
  inside a `run:` line.
- [x] **Step 5 - Docs** - `coding-standards.md` "Merging" names "PR title"
  among the required checks and says CI runs `scripts/verify.ps1` in two jobs.
  *Done when:* the text is there and a full Verify passes.

## Security

- No new app surface.
- The workflows keep `permissions: contents: read` and the `pull_request`
  trigger. Never use `pull_request_target`.
- The PR title is untrusted input. It goes in through `env:` only, never as
  `${{ }}` inside a script, which prevents script injection.
- SHA pins stop a moved tag from changing what CI runs.
- CI starts from a fresh checkout with no `.verify/evidence.json`, and the
  tests forbid `-ReuseIfCurrent` in CI, so CI always runs every check itself.
- The step 1 Linux container gets a copy of the tracked files only
  (`git ls-files`), never the working tree, so git-ignored `.env` files are
  never mounted.
- Uploaded logs hold test output only. Server tests use Testcontainers fixtures
  and no real connection strings.

## Notes for the AI

- Keep `ci.yml` free of logic of its own. Each job sets up its tools and calls
  `verify.ps1`; any new check belongs in `verify.ps1`, not in YAML.
- `ubuntu-latest` has `pwsh` and Docker preinstalled; Verify's Docker check
  then passes. Keep `dotnet-version: 10.0.x` and `node-version: 24`.
- Removing coverage: the current CI uploads coverage artifacts that nothing
  reads (no threshold, no badge), and keeping them would mean running tests a
  second way outside Verify. If you want coverage back, add a switch to
  `verify.ps1` in a later item.
- Dependabot titles with the `chore` prefix come out as `chore: bump ...`, which
  passes the title check. If one runs over 72 characters, edit the PR title by
  hand. Do not loosen the rule.
- Closes F-28 (`blueprint/history/fixes/2026-10-25-verify-evidence.md`). Record
  that in this item's history file at `/complete`.
- Workflow tests use the existing `Assert-True` style of the other
  `scripts/tests/*.tests.ps1`, with no new test framework.
