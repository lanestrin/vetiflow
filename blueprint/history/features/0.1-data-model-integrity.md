# Feature: Data model integrity

**From build-plan:** feature 0.1
**Status:** complete
**Branch:** `feature/data-model-integrity`

> Backfilled when the workflow was set up. Written from the merged commit
> (`4aafbe2`, PR #12), not from an original spec.

## Goal

Make the database enforce the rules the ER board depends on, so bad data
cannot get in regardless of what the API does.

## In scope

- Real foreign keys for staff and room references, all `ON DELETE RESTRICT`.
- Partial unique indexes: one active case per patient and per room
  (`DischargedAt IS NULL`).
- Enums stored as text; the migration converts existing integer rows by name
  (`EnumColumnMigration`).
- `PatientSex` enum. `Room.IsAvailable` dropped, since availability is derived
  from active cases.
- Current acuity set only through `EmergencyCase.RecordTriage`.
- New `CaseTask` entity for tasks and blockers.
- Migrations and seeding on startup; a richer demo seed.

## Out of scope

- `Owner` and repeated vitals (0.2). Renaming `Stable` to `High` (0.3).
- Making startup migrations configurable (S.1).

- Enum columns hold the C# member name as text. Renames need a data migration.
- Deletes never cascade; history rows are the audit trail.
