# Feature: Board table

**From build-plan:** feature 2.25
**Status:** complete
**Branch:** `feature/board-table`
**Audit:** not needed - client-only presentation change; no API, auth, data or owner-scope changes.

## Goal

Replace the acuity lanes with the prototype's patient table on desktop, and with compact patient cards on phones. Staff then scan identity, acuity, care stage and care team in one list (Board layout decision, 2026-11-02). Also put the UI/UX alignment items first in the build plan, as the person asked.

- the `.board` table: `thead`, `tbody tr`, `.patient`, `.pill`, `.assignment-line`;
- the `@media (max-width: 700px)` card rows.

`VetiFlow-Product-Rules.md` sections 2, 3 and 14. The prototype guides hierarchy, not exact pixels.

## In scope

- **Build plan order.** Move the "ER board prototype alignment" section above 4.13b's section, so `/feature` with no ID takes 2.25, 3.2c, 3.2d, 2.26, 2.27, 2.28 and 4.1c before 4.13b. Update the "Build the simplest working version first" order line to match. No item text or ID changes.
- **The board table** in `PatientFlowBoard`: a semantic `<table>` with a visually hidden caption and five columns.
  - **Patient:** a decorative species icon (dog, cat, or a generic paw for other species), then the name as a button, then a muted "Species · breed · age" line.
  - **Acuity:** the existing `AcuityBadge`. It shows "Critical", "Urgent" or "Stable" as text, "<Priority> · provisional" for an incoming case, and "Not triaged" for no acuity.
  - **Care stage:** the stage label, then a muted elapsed-time line labelled by its meaning: "12 min in stage", or "Waiting 12 min" from arrival for an incoming case. Open blockers show as an alert line with text ("1 open blocker" or "2 open blockers"), not colour alone.
  - **Care team:** two lines, "Tech" then "Vet", from `assignedTechnician` and `assignedDoctor`, each showing "Unassigned" (distinct styling plus the word) when missing.
  - **An empty header cell** for a decorative chevron.
- **Row order and selection.**
  - Rows follow the API's order (not triaged, then Critical, Urgent, Stable).
  - While **Priority** is pressed, rows show longest in stage first within each acuity group, so the grouping is kept.
  - The selected row has a highlighted background and a teal inset edge. The name button keeps `aria-pressed`, so keyboard and screen-reader selection work as now. A mouse click anywhere on the row selects it too.
- **Kept as they are:** the title row (renamed "Patient board", keeping the live "Updated just now · N active cases" line), the Incoming toggle, the Filter menu, Priority, the stat-card filters, the top-bar search, the footer text and the "Search all patients" link.
  - The Critical filter footer reads "other acuities hidden" instead of "other acuity lanes hidden".
  - The Critical stat-card filter shows only critical rows.
- **Empty states**, as one row spanning the table:
  - "No patients on the board" when there are no cases;
  - "No patients match" when filters or search hide every case. The footer still offers the Patients search.
- **Phone cards** (at the app's existing 650 px phone breakpoint).
  - Each row becomes a bordered card: patient top-left, acuity top-right, then Care stage and Care team side by side, each with a visible label ("Care stage", "Care team").
  - The `thead` is visually hidden, not removed, and the chevron is hidden.
  - No horizontal page scroll at 320 px.
- **Removed:** the lanes, the lane tabs, the lane count chips, the "Not triaged" lane, `PatientCard.tsx` with its test and styles, and the wait chip and owner · complaint line on rows. The search still matches the owner and complaint, and the panel shows them.

## Notes for the AI

- Reuse `AcuityBadge`, `ageLabel`, `stageLabel`, `minutesSince`, `matchesSearch`, `matchesMenuFilters` and `sortByLongestInStage`. No new packages and no new abstraction beyond the row component.
- Keep the existing tokens and focus treatment (1px `--color-focus-on-light`). Add a token only for a real shared colour; do not copy the prototype's hex values where an existing acuity or shell token fits.
- The row-level click is a mouse convenience only. The name button stays the keyboard and assistive-technology control, so no `tabindex` on `tr`.
- Use `rem` for text, and wrap long names and breeds instead of clipping them.
- Comments follow the house style ("The prototype's ...", build-plan IDs).

## Defaults chosen (the prototype is silent; say if you want any changed)

- **Wait chip** (STAT / New / Ready / Recheck / minutes): removed from rows. STAT, New and Recheck repeat the acuity or stage now shown in its own column. Minutes are shown with their meaning in the Care stage cell. Ready remains visible as case status in the panel.
- **Open blockers:** shown as a count in the row, with the full text in the panel.
- **Owner and complaint:** off the row (product rules: keep narratives out of rows); still searchable.
- **Phone breakpoint:** the app's existing 650 px rather than the prototype's 700 px. 2.27 owns the layout breakpoints.
