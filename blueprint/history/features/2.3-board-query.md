## Goal

The board shows only patients still in the ER, the sickest and longest
waiting first, and each case carries who is on it, where it is, what blocks
it and when it last changed, ready for the cards (3.3) and timers (2.8)
[14–16].

## In scope

- `GET /api/cases` returns active cases only (`DischargedAt IS NULL`), so
  discharged patients leave the lanes and the "Patients in ER" count (moved
  here from 2.9). Today it returns every case, newest first.
- Order: by acuity, Critical, Urgent, High, Low (enums are stored as text, so
  the query maps them to a rank; alphabetical would be wrong), with untriaged
  cases first (see Decisions); then by arrival time, oldest first
  (longest wait). The lanes keep the server's order.
- New fields on each list item:
  - `assignedDoctor` and `assignedTechnician`: `{ id, name }` or `null`
  - `room`: `{ id, name }` or `null`
  - `blockers`: the open `Blocker` tasks as `{ id, description }`, oldest
    first, empty when none
  - `lastUpdated`
- One query: projected with `Select`, so no N+1.
- Client: the types and test builder gain the fields. Nothing new is drawn
  yet; showing staff, room and blockers on the card is 3.3.

## Out of scope

- Showing the new fields on the card (3.3); timer colours (2.8).
- Filtering and search (2.14); stage rules (2.1); sign-in on the endpoint
  (S.17).
- Discharging a case (6.2); this only reads `DischargedAt`.

## Data / contracts

- No entity, column or migration change.
- `GET /api/cases`: active cases only, ordered as above. New camelCase
  fields:
  - `assignedDoctor: { id, name } | null`
  - `assignedTechnician: { id, name } | null`
  - `room: { id, name } | null`
  - `blockers: { id, description }[]`
  - `lastUpdated: string`

  `name` is the staff member's first and last name, or the room name.
  Existing fields are unchanged.
- Hub: unchanged (`caseUpdated` with the case ID; the client refetches).

## Security

- No new endpoint. The list still carries no owner details
  (`GetCases_DoesNotExposeOwnerDetails`).
- Blocker descriptions are staff-written text on a staff-only board (it is
  locked to team members in S.17). They never go in hub messages or logs.

## Notes for the AI

- Rank acuity in the query with a conditional (EF translates it to SQL
  `CASE`); never `OrderBy(c => c.Acuity)` on the text column.
- Build the blocker list inside the projection
  (`emergencyCase.Tasks.Where(...).OrderBy(...).Select(...).ToList()`); EF
  loads it in the same query.
- Extend `TestData` with `StaffMember()` and a blocker helper instead of
  building entities by hand in tests.

## Decisions

- **Untriaged cases sort first** (2026-10-26): above Critical, oldest first,
  because their risk is unknown and the next step is triage. Order:
  untriaged, Critical, Urgent, High, Low; then longest wait.
