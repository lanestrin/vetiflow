## Goal

Each clinician has a status (Available, Busy, At limit, Unavailable) on their
staff record. They can read and set their own, and the board can list the
clinicians on the floor (anyone not Unavailable) with their status and active
case count. This is the back end for My status (2.21b), the shift chip's
"4 clinicians on floor" (2.15a) and Workload & team (2.22).

## In scope

- **Who is a clinician:** staff with the Veterinarian or Technician role
  (decided 2026-10-29; it matches the card, whose clinician is the doctor,
  else the technician). Assistants, receptionists and managers have no status
  and are never listed.
- **The status:** a new `StaffStatus` enum, `Available`, `Busy`, `AtLimit` and
  `Unavailable`, on `StaffMember.Status`. It is stored as text, like every
  enum, and every staff member has one. The starting value is `Unavailable`
  (decided 2026-10-29 with the spec's OK), so nobody counts as on the floor
  until they say so. Databases that already exist, including the Render demo,
  show nobody on the floor until someone sets a status.
- **Read my status:** `GET /api/staff/me/status` returns `{ "status": "busy" }`
  for the signed-in clinician.
- **Set my status:** `PUT /api/staff/me/status` with `{ "status": "atLimit" }`
  saves it and returns `204`. It changes only the signed-in clinician's own
  record. There is no route that takes a staff ID.
- **Clinicians on floor:** `GET /api/staff/on-floor` lists active
  (`IsActive`) clinicians whose status is not Unavailable, by last name then
  first name. Each item has the id, display name ("Dr. Jordan Lee" for a
  veterinarian, as `/api/auth/me` shows it), initials, role, status, and active
  case count. The count is the cases not discharged where they are the
  assigned doctor or technician. It is one query, with no N+1.
- **Demo data:** the seeder gives the four seeded clinicians the prototype's
  mix (Lee Busy, Shah Available, Ortiz Available, Kim Busy), so a fresh demo
  has people on the floor.

## Out of scope

- The My status selector and its toast (2.21b). The shift chip (2.15a/b).
  Workload & team (2.22) and the Team page (4.5).
- A hub message for status changes. Nothing listens yet. 2.15b or 2.22 adds
  one when a screen must update live.
- Setting someone else's status, or roles and policies (S.6). Managing staff
  and assigning roles to accounts (9.1).
- "At limit" worked out from the case load. It is only what the clinician
  chooses.

## Data / contracts

- **Enum `StaffStatus`:** `Available`, `Busy`, `AtLimit`, `Unavailable`,
  stored as text. JSON values are `available`, `busy`, `atLimit` and
  `unavailable`. Later items must keep these names; renaming one needs a data
  migration.
- **Column:** `StaffMembers.Status`, text, not null, with the starting value as
  the database default so existing rows get it. Migration `AddStaffStatus`.
  The table already has its grant and RLS, so nothing more is needed.
- **`GET /api/staff/me/status`:** `200 { status }`; `401` signed out; `403`
  for a pet parent or a staff member who is not a veterinarian or technician.
- **`PUT /api/staff/me/status`:** body `{ status }`, which is required, known
  names only, numbers rejected. Returns `204`; `400` ProblemDetails for an
  invalid body; `401` and `403` as above.
- **`GET /api/staff/on-floor`:** `200 [{ id, displayName, initials, role,
  status, activeCaseCount }]`, an empty array when nobody is on the floor;
  `401` signed out; `403` for a pet parent. Any team member may read it.
- **Hub messages:** none.

## Security

- Every route requires the team member policy (`AuthNames.TeamMemberPolicy`),
  like `BoardController`. Pet parents get `403` and never see staff.
- `me` is the staff record linked to the signed-in account
  (`Account.StaffMemberId`, as `CaseTriageController` finds it). There is no
  staff ID in any route or body, so nobody can set another person's status.
- The list returns names, initials, role, status and a count. It holds no
  contact details, account email or phone, and nothing from any case.
- Status changes are not logged with names.
